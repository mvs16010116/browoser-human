# ADR-001 强风控站点走扩展通道，读路径按成本分级

- 状态：已接受
- 日期：2026-11-18
- 决策者：browser-human 维护者（AI 以领域专家身份自决，依据见各条「依据」）
- 关联：`docs/glossary.md`、`docs/spec.md`、`docs/tickets.md`

## 背景

同一台机器、同一份 Chrome profile、同一批登录态，用 `kimi-webbridge`（浏览器扩展 + 本地 daemon，`http://127.0.0.1:10086`）访问站点不会被风控，用 `browser-human`（Playwright `connectOverCDP` 附着）访问会在若干站点被拦。需要给出**根因**与**可持续**的处置，而不是继续叠加 DOM 级伪装。

同时，agent 使用本服务时的主要成本不是点击，而是**把页面文本搬进上下文**：`page_text` / `get_accessibility_tree` / `screenshot` 的输出体积直接决定 token 消耗。

## 根因（已核实）

Playwright 附着 CDP 时会向每个页面自动发送三条协议命令，页面内的 JS 可以稳定观测到：

| 命令 | 来源 | 页面内可观测的特征 |
|---|---|---|
| `Runtime.enable` | Playwright 建立/恢复会话（`packages/playwright-core/.../crPage.js`） | `Error.prepareStackTrace` 拿不到调用栈 / `console.debug` 触发时机异常 / 已知的 "Runtime.enable 探针" |
| `Target.setAutoAttach({ waitForDebuggerOnStart: true })` | 同上 | worker / iframe 启动被 debugger 暂停，`performance.now()` 与 `requestAnimationFrame` 出现异常停顿 |
| `Emulation.setFocusEmulationEnabled({ enabled: true })` | 同上 | 后台标签页里 `document.visibilityState === "hidden"` 但 `document.hasFocus() === true`，两者矛盾 |

kimi-webbridge 走扩展的 `chrome.*` 通道，不建立 CDP 会话，上述三条都不存在；它的写操作是 DOM 合成事件（`isTrusted=false`），读操作是扩展侧 `snapshot`。因此差异**不在输入事件拟人度**（本项目的 CDP `Input` 事件 `isTrusted=true`，反而更真），而在**协议痕迹**。

判定：只要本服务用 `connectOverCDP` 驱动某个站点，该站点就一定处于「可被识别为 CDP 自动化」的状态，任何 JS/DOM 级对抗都只是提高门槛，无法消除。

## 决策

### D1 读写分离双通道，而不是继续加固 CDP 伪装

- **写**：强风控站点由 agent 改走 kimi-webbridge 通道；普通站点继续走本服务 CDP。
- 本服务提供**站点策略表 + 路由决策**，在导航与 `page_info` 中明确返回当前通道与判定原因，把「该不该用这条通道」变成显式信息，而不是隐含假设。
- **依据**：分层/单一职责（每条通道只做它能做干净的事）；也符合「最小意外原则」——同一工具在强风控站点静默失败是最坏体验。

### D2 不做 JS 层对抗 `Runtime.enable` 探针

- 拒绝：重写 `Error.prepareStackTrace`、拦截 `console.debug`、伪造 `performance`。这类补丁互相牵连、随 Chrome 版本失效，且会制造新的不一致特征（页面里出现不该存在的函数被改写）。
- **依据**：安全领域的「检测与反检测不对称」——防御方只需一个未被覆盖的探针即可判定；补丁面积越大，自身特征越明显。

### D3 CDP 通道整改到「无矛盾特征」，而非「无特征」

在不改动工具签名的前提下修掉自造的矛盾：

1. `open_browser` 增加可选 `foreground`（默认 `false`）。为 `true` 时对新页 `bringToFront()`，让窗口/标签真实前置——写操作需要焦点时才付这个代价。
2. 新建页后对该页 CDP 会话下发 `Emulation.setFocusEmulationEnabled({ enabled: false })`，消除「hidden 却有焦点」的矛盾。
3. 所有 `human_*` 公共入口增加**可见性前置断言**：页面 `visibilityState !== "visible"` 时先尝试激活，仍不可见则明确报错，不静默发送注定被丢弃的输入。
4. `human_click` / `human_double_click` 内部先做 2~3 段贝塞尔移动（不新增工具、不返回中间态），补齐「瞬间瞬移点击」这一行为特征。
5. `human_type` 按 8~12 字符分块，块间停 50~150ms，避免整段字符串一次性注入。
6. 指纹自检写入 `logs/fingerprint.log`；仅 `DEBUG_FINGERPRINT=1` 时随 `page_info` 返回。

- **依据**：可观测一致性优先于特征隐藏（同一份浏览器状态里不该同时存在互斥的两个值）；批处理输入是最容易被行为风控统计的节奏特征（固定间隔、零间隔）。
- **冲突记录**：项目原 README 声明「绝不抢焦点」。为消除 hidden/hasFocus 矛盾，可见性断言在必要时会激活页面。取舍：**默认仍不抢焦点**（仅 `foreground:true` 或显式写操作时激活），把「真实前置」限定在必要场景，而不是全局改变行为。

### D4 读路径按成本分级，且必须可截断

优先级：`capture_network` 重放 → `evaluate` 结构化取值 → 扩展 `snapshot`（@e refs）→ `page_text`（最后手段）。

`page_text` 收口为：`selector` 可选（默认 `body`）、`maxChars` 默认 8000、超限截断并回报**剩余字符数**。

- **依据**：token 成本 = 输出字符数；`innerText` 已排除脚本/样式与隐藏节点，`selector` 让 agent 按需取局部，截断回报让 agent 知道「还有多少没读」而不是盲目重读。
- **不做**：自动摘要、自动分页。摘要会引入不可验证的信息损失；分页应由 agent 按需发起。

## 后果

正向：
- 强风控站点有明确的替代路径，不再出现「看起来能用、实际被拦」的隐性失败。
- CDP 通道自身矛盾特征消失，被识别门槛回到「协议痕迹」这一不可消除的底线上。
- 读路径的 token 上限可预期、可截断、可局部化。

代价：
- 站点策略表需要人工维护（`MCP_STRICT_SITES` 环境变量，逗号分隔域名后缀），新站点的判定依赖实际观测。
- `foreground:true` 与可见性断言会在必要时把标签前置，与「完全不打扰用户」有取舍（已在 D3 限定范围）。
- 输入事件仍是 CDP `Input`，`isTrusted=true`；扩展通道的 `click`/`fill` 是 `isTrusted=false`。两条通道各有边界，文档需同时写明。

## 未采纳的备选

| 备选 | 否决理由 |
|---|---|
| 自研扩展宿主替代 kimi-webbridge | 需要维护扩展 + daemon + 协议，成本远超收益；kimi-webbridge 已具备 navigate/click/fill/snapshot |
| 伪造 UA / 屏幕 / 插件 / WebGL | 跑在真实 profile 上，这些值本来就是真的，伪造只会制造新矛盾 |
| 关掉 `capture_network` 以降低痕迹 | Playwright 的网络事件不依赖 `Runtime.enable` 的 DOM 探针，且它是省 token 的主路径，收益为负 |
| 用 `chromium.launchServer` + 独立 profile | 丢失真实登录态与扩展，违反项目「不启动替代浏览器」的核心约束 |
